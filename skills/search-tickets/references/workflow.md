# عقد التنفيذ وسجل التغطية

## النطاق والأدلة

البحث العام لا يحل محل البحث الداخلي. سجّل الاستعلام الفعلي والأسماء البديلة والمرشحات والصفحات المفحوصة. عند عدم العثور بعد بحث محدد، اذكر حدود هذا البحث؛ لا تقل إن النظام كله لا يحمل المناسبة. تذاكر الضيافة والفندق والجولات فئات مستقلة عن مقعد عادي. لا تصف بائع إعادة البيع بأنه رسمي إلا بدليل خاص بالمناسبة.

قبل الانتقال إلى مقارنة حية، طابق المباراة مع المصدر الرسمي؛ مثال: Sporting وBenfica ناديان مختلفان، و2025 و2027 مناسبتان مختلفتان. تسميات إعادة البيع لا تثبت هوية الحدث. إن تعارضت الرسمية مع المنصة ضعها غير محسومة، ولا تمنحها سعرًا مؤهلًا للتوصية.

حدد نطاق البلدان ونوع المناسبة وعدد المقاعد والجمهور. افحص كل منصة ذات صلة في النطاق المعلن أو سجّل عائقًا فعليًا. لا تقلل النطاق بعد التعثر لإخفاء المنصات؛ أي توسع أو استبعاد لاحق يحتاج سببًا مؤرخًا. الفرق بين منصتين متشابهتي الاسم مهم: Fanpass.net مستقل عن FansPass.sa، وStubHub.com مستقل عن StubHub International في التحقق والمخزون والرسوم والحساب.

## درجات الدليل

| evidence_level | ماذا تثبت؟ |
| --- | --- |
| discovery | نتيجة بحث عام أو رابط مرشح فقط |
| page | فتح صفحة؛ لا يثبت بحث المخزون أو توفر العرض |
| internal_search | بحث داخلي محدد مع تسجيل الاستعلام ونطاق النتائج |
| listing | صفحة المناسبة/العرض مع العدد والشروط المرئية |
| checkout | شاشة إجمالي المنصة للعرض والعدد وشروط الدفع المفحوصة |

الطريقة `method` تصف الأداة الفعلية مثل browser أو HTTP أو Firecrawl؛ لا تُحوّل جلب HTML إلى تصفح تفاعلي. سجل العطل الخاص بالأداة والمنصة، وجرّب الوسائل المستقلة المتاحة دون تجاوز تحقق بشري أو قيود دخول.

## حقول كل نتيجة

كل صف في `coverage` يحمل `platform_id, status, checked_at, url, method, evidence_level, evidence`. الوقت ISO 8601 بمنطقة زمنية؛ الرابط عام HTTPS للمناسبة أو المصدر، دون رابط دفع/معرف طلب/جلسة/معلومات شخصية. `targets` يشمل معرّفات الصفوف مرة واحدة. احتفظ بوصف المورد الأصلي للمقعد مع الفئة الموحدة.

الحالات:

| status | الاستخدام |
| --- | --- |
| final_total_confirmed | عرض محدد بإجمالي نهائي مستوفٍ لشروط أدناه |
| offer_fees_unconfirmed | عرض موجود، وإجمالي الرسوم أو الشروط غير محسوم |
| event_no_offers | صفحة مناسبة مطابقة تعرض عدم وجود عروض وقت الفحص |
| event_not_found | لم تظهر المناسبة بعد بحث داخلي محدد موثق |
| login_required | الخطوة اللازمة تحتاج جلسة مستخدم |
| business_account_required | المخزون/الطلب يحتاج حسابًا تجاريًا |
| human_verification | تحقق بشري أو حظر فعلي موثق |
| technical_error | عطل محدد مثل HTTP 502 أو واجهة لا تحمل النتائج |
| not_applicable | خارج نوع المناسبة أو البلد، مع `reason` مثبت |
| not_checked | لم ينفذ الفحص؛ إبقاؤه ظاهرًا ضرورة، ولا يُسمى عائق وصول مثبتًا |

جميع الحالات غير المحسومة تحمل `blocker` و`next_step` محددين. عدم العثور ونفاد العروض حالتان مختلفتان. لا تسجل no_offers من نتيجة محرك بحث. `not_applicable` يحتاج سبب صلة، لا افتراض أن منصة أمريكية لا تعرض أبدًا حدثًا أوروبيًا.

## متطلبات إجمالي مؤكد

`event.official_verified=true` مع `official_sources` (URL، وقت، دليل)، ثم في الصف:

- `event_matched=true`، `quantity` مطابق، `evidence_level=checkout`، و`fee_conflict_resolved=true`.
- `cheapest_offer_verified=true` و`cheapest_scope=platform` فقط عند فحص أدنى عرض مستوفٍ للشروط ضمن الفرز المفحوص. إذا تعذر الأدنى: `cheapest_offer_verified=false`، `cheapest_scope=verified_offer_only`، و`min_listing_blocker` يشرح العائق.
- `total.amount` إجمالي كل التذاكر المطلوبة، لا سعر التذكرة الواحدة. `currency` رمز ISO؛ `charged_in_sar` يوضح عملة التحصيل.
- `total.checkout_verified=true, mandatory_fees_complete=true, optional_excluded=true`؛ `payment_assumption` يحدد طريقة الدفع/شرط الرسوم الذي فُحص. قول «غير معروفة» لا يحقق الشرط؛ إذا تحتاج المنصة بطاقة أو عنوانًا قبل إظهار الرسم، فالنتيجة غير محسومة.
- عند عملة أجنبية: `fx_rate_to_sar, fx_source, fx_checked_at`، مع الاحتفاظ بالأصل. الناتج تحويل للمقارنة وليس وعدًا بسعر البطاقة؛ لا تصف رسوم البنك المجهولة بأنها مشمولة.
- `seat.description, view, supporter, eligibility`؛ `adjacency_confirmed=true` عند طلب التجاور. «غير مذكور» حالة شرط ناقص إذا يؤثر في طلب العميل، لا تأكيد ملاءمة.
- `delivery.method, deadline` مع شروط التحويل/الهوية/الإطلاق إن كانت منشورة؛ «قبل الحدث» دون موعد أدق يُعرض كما قاله المصدر، دون اختراع ضمان.

أضف تفصيل الرسوم عندما يظهر واسم/رابط العرض الثابت إن توفر، ورقم الدليل المحلي المنقح. التنقل إلى شاشة السعر مأذون؛ يمكن متابعة نافذة شرح تبدأ عدادًا تلقائيًا إذا لم ترسل طلبًا أو تقبل شروطًا أو تنشئ التزامًا. افحص تسمية الزر والنص المحيط قبل المتابعة. لا تضغط زر شراء/دفع/حجز ملزم أو توافق على الشروط لإجبار المدقق على النجاح. حالة المدقق الناجحة لا تصدّق الادعاءات؛ مراجعة الدليل جزء من التنفيذ.

## العد والتسليم

`targeted`: جميع الأهداف. `final_totals`: صفوف الإجمالي النهائي. `closed_without_quote`: لا عروض أو لم أجد بعد البحث أو غير مناسب مسببًا. `checked_complete`: نتائج مغلقة بلا سعر + إجماليات حُسم فحص أدنى عروضها. عرض مؤكد مع تعذر الأرخص يبقى ضمن غير المحسوم من جهة التغطية. `unresolved`: بقية الأهداف. اكتمال الفحص لا يعني وجود سعر لكل منصة؛ اعرض الإجماليات المؤكدة منفصلة.

ترتيب النتيجة: أرخص عرض مؤكد وحدود نطاقه → جدول المقارنة الكامل → العوائق والخطوات. إن لم يوجد إجمالي مؤكد قل ذلك مباشرة. لا تقارن عرض ضيافة بمقعد عادي على أنهما متكافئان. الأسعار التاريخية مرجع لاختبار المنهج فقط؛ أعد التحقق من كل عرض حالي.
